# 에이전트 협업 가이드 (Claude Code · Codex)

Claude Code와 Codex로 `milab-pnu`와 과목 repo를 작업할 때의 **도구 협업 규칙 정본**이다.
강의 작성·검토 규칙은 `lecture-authoring.md`, 사이트 동작은 `lecture-site-reference.md`,
사이트 구조는 `../README.md`. 한 도구만 써도 되고, "두 도구를 함께 쓸 때" 절은 그때만 적용한다.

## 공통

- **시작 위치.** 강의 작업은 `pnu/lectures/`, 사이트 작업은 `pnu/milab-pnu/`에서 시작한다.
- **지침 파일.** 각 폴더의 `AGENTS.md`가 원본이고 `CLAUDE.md`는 그 심볼릭 링크다. 링크를 일반
  파일로 덮어쓰지 않는다. 도구별 설정(`.claude/`, `.codex/`)에 공통 규칙을 복제하지 않고 커밋하지도 않는다.
- **과목 `AGENTS.md`는 직접 읽는다.** Claude Code는 상위 폴더와 작업 중 들어간 하위 폴더의 `CLAUDE.md`를
  불러오지만, Codex는 시작할 때 git 루트부터 시작 폴더까지의 `AGENTS.md`만 읽는다. `pnu/lectures/`는 git
  repo가 아니라서 Codex는 어디서 시작하든 과목 규칙이나 상위 규칙 하나를 놓칠 수 있다.
- **커밋·push.** 실제 참여한 도구의 `Co-Authored-By`를 붙이고(리뷰 반영도 참여), 과목 repo는 알아서
  push, `milab-pnu`는 물어본다. 표기는 `lecture-authoring.md` "커밋과 push".
- **인수인계 파일은 만들지 않는다.** 맥락은 커밋 기록과 대화로 넘기고, 넘기기 전에 커밋한다.

## 두 도구를 함께 쓸 때

### 역할

- 작성·리뷰 역할은 **작업마다 사용자가 정한다.** 정하지 않았으면 작업을 받은 도구가 작성자다.
- 리뷰어는 문서 **전체**를 `lecture-authoring.md` "검토 기준"으로 보고, 이전 라운드 뒤의 변경은
  diff(`git diff`, `git show`)로 확인한다. 과목 `AGENTS.md` 규칙과 `npm run build` 결과도 본다. 지적만 하고
  (파일·줄·근거), 수정은 요청받을 때만 한다.

### 자동 리뷰 루프 (debate)

사용자가 "알아서 주고받아 완결하라"고 하면 작성 도구가 리뷰 도구를 읽기 전용 비대화 모드로 불러
합의할 때까지 반복한다. 지적을 받아 적는 것이 아니라 서로 따져 하나의 완결된 자료를 만든다.

1. 작성자가 커밋하고 리뷰어를 부른다. **작성자의 요약이나 검토 포인트는 주지 않는다**(리뷰가 거기에
   맞춰진다). 대상 파일, 지침 문서, 원자료 경로, 사용자가 정한 조건만 준다. 지적 형식은
   `[심각도] 파일:줄 — 문제 — 근거 — 제안`, 마지막 줄은 `VERDICT: APPROVE` 또는 `VERDICT: CHANGES`.
2. 작성자도 같은 기준으로 독립 검토하고, 지적마다 **수용 / 부분 수용 / 반박**을 근거와 함께 정해
   고친 뒤 커밋한다.
3. 같은 리뷰 세션을 이어 새 diff·반박·작성자가 찾은 문제를 보내고, 리뷰어는 재반박하거나 받아들인 뒤
   전체를 다시 본다.
4. **리뷰어 `APPROVE`와 작성자 동의가 모두 있고 열린 쟁점이 없을 때** 끝낸다. 합의되지 않는 쟁점은
   양쪽 근거를 정리해 사용자에게 넘긴다. 끝나면 두 도구의 `Co-Authored-By`로 커밋·push하고,
   바뀐 내용·쟁점별 결론(누가 양보했는지)·사용자 결정 항목을 보고한다.

**사실 검증 모드.** 수치·설정·인용을 원자료와 집중 대조할 때는 일반 리뷰와 따로 돌린다. 기본 설정에서도
URL은 열 수 있지만, 검색이 필요한 자료까지 찾게 하려면 웹 검색을 켠다(`codex --search exec …`).

- 범위 안의 주장을 빠짐없이 표로: `파일:줄 | 주장 | 실제로 연 1차 자료 URL과 위치 | 원자료 값(짧은
  인용) | 일치 / 불일치 / 부분 일치 / 확인 불가`. 계산값은 원자료 값으로 다시 계산한다.
- 1차 자료는 원논문·기술 보고서, 공식 config·구현·모델 카드, 그리고 개발사 자신의 주장에 한해 개발사의
  공식 발표다. 요약 블로그·위키는 인정하지 않는다. 기억으로 판정하지 않고 열지 못하면 "확인 불가"다.
- 작성자도 같은 범위를 독립 대조하고, 한쪽만 문제로 본 항목은 원자료를 다시 연다. 리뷰어가 이미지를
  판독하지 못해 "확인 불가"로 남긴 그림은 작성자가 직접 열어 확인한다.
- 그림·표·절 번호는 판본(arXiv 버전, PDF·HTML)마다 다를 수 있다. 불일치로 판정하기 전에 판본을 맞추고,
  노트에는 인용한 판본 기준 번호를 쓴다.

**운영 메모.**

- 라운드 기록은 repo 밖(작성 도구의 임시 폴더)에 둔다.
- 리뷰어는 읽기 전용이라 "한 repo 한 도구" 규칙과 충돌하지 않는다. PDF를 못 읽으면 추출 텍스트 경로를 준다.
- 리뷰어 샌드박스는 `localhost:4321`에 못 붙는다. 렌더 확인은 작성자가 하고 결과를 전한다.
  리뷰어의 "렌더 확인 불가"는 문서 오류가 아니다.
- 노트 여러 개를 서브에이전트로 병렬 검토하면 담당마다 자기 노트 파일 하나만 고치고 커밋은 부모가 파일 단위로 한다.

### Codex 호출

effort는 사용자가 정한다(`~/.codex/config.toml` 기본은 `low`). 흐름·구성까지 보는 첫 검토는 `medium` 이상,
이미 검토된 노트의 사실·출처·표기 재점검은 `low`로도 오탐 없이 돌았다(low는 지적이 짧고 규칙 위반·수치 위주이며
흐름·문장 지적은 거의 내지 않는다).

```sh
cd <과목 repo>   # git repo나 config.toml에 등록된 trusted 폴더 밖에서는 "Not inside a trusted directory"
codex exec -m <모델> -c model_reasoning_effort="medium" -s read-only -C . \
  -o <임시폴더>/r1-out.md --json "<프롬프트>" </dev/null > <임시폴더>/r1.jsonl; echo done > <임시폴더>/r1.done
# 세션 id: r1.jsonl 의 thread.started 이벤트
codex exec resume <id> -c model="<모델>" -c model_reasoning_effort="medium" \
  -c sandbox_mode="read-only" -o <임시폴더>/r2-out.md --json "<프롬프트>" </dev/null > <임시폴더>/r2.jsonl; echo done > <임시폴더>/r2.done
```

- `resume`은 `-s`·`-C`를 받지 않고(Usage 오류) 모델·effort도 잊는다. 모델을 빠뜨리면 "recorded with model X
  but resuming with Y" 경고와 함께 기본 모델로 도니, 위처럼 `-c`로 매번 다시 준다.
- 프롬프트를 인자로 넘기면서 stdin이 열려 있으면 "Reading additional input from stdin"으로 멈추니 `</dev/null`을 붙인다.
- 끝났는지는 호출마다 만드는 완료 표시 파일(`.done`)이나 `wait`으로 본다(`-o` 출력 파일은 끝날 때 생긴다). `pgrep -f`로 출력 경로를 찾으면 그 경로가 든
  대기 루프 자신이 잡히고, `codex --search exec`는 `pgrep -f "codex exec"`에 안 잡힌다. 끝나기 전에
  resume하면 "thread already has an active writer"로 실패한다. macOS에는 `timeout`이 없다.

### 동시 작업

- **한 작업 트리는 한 도구만 수정한다.** 병렬로 하려면 과목을 나누거나 `git worktree`를 쓴다.
- 여러 세션이 한 repo를 쓰게 되면 `git add -A`를 쓰지 않고 자기 파일만 `git add <파일>`로 담는다
  (다른 세션의 편집이 커밋에 딸려 들어간 적이 있다).
- 같은 주차 노트를 여러 세션이 나눠 고칠 때는 그림·사례를 넣기 전과 커밋 직전에 형제 노트의 작업
  트리를 `grep`해 같은 그림 URL·논문 설명이 있는지 본다. 겹치면 앞 노트에 두고 뒤 노트는 가리킨다.
- `milab-pnu` 빌드·개발 서버도 한 번에 한 도구만 다룬다(`lecture-site-reference.md` "개발 서버 실행 중 빌드").

## 이 문서 관리

협업 방식이 바뀌면 이 문서를 고치고 `milab-pnu`에 커밋한다. 각 `AGENTS.md`에는 요약과 이 문서
링크만 둔다.
