# 강의 노트 작성·검토 규칙

강의 노트를 쓰고 검토할 때 지키는 **과목 공통 규칙의 정본**이다. 규칙은 핵심 한 문장과
예시 하나로 적는다.

- 과목별 합의(참고문헌 구성·파일명·수업 형식)는 과목 repo의 `AGENTS.md`에 둔다(없으면 만들고
  `CLAUDE.md`를 그 심볼릭 링크로 둔다). 한 과목의 선호를 다른 과목에 자동 적용하지 않는다.
- frontmatter·컴포넌트·각주 동작·이미지·공개 주차·새 강의 추가·빌드 설계 배경은
  `lecture-site-reference.md`에서 찾는다.
- 도구 협업(역할·자동 리뷰 루프)은 `agent-workflow.md`, 시스템(sync·CI·배포)은
  `../README.md`의 "강의 페이지" 절.

## 목표

주차 노트는 **강의를 대체할 수 있는 읽을거리**다. 수업에 오지 않은 학생이 노트만 읽고도 그
주차 내용을 높은 수준으로 이해하고 자기 프로젝트에 적용할 수 있어야 한다. 강의자의 말을
전제한 슬라이드 요약이 아니라 글만으로 완결되는 설명이며, 분량 제한은 없다.

## 작성 절차

1. **범위를 받는다.** 다룰 내용, 서베이·교재의 절·페이지, 과목의 강조점(이론 깊이·구현·응용)은
   사용자가 정한다. 기존 주제와 노트 제목은 가독성을 고친다는 이유로 바꾸지 않는다.
2. **자료를 조사한다.** 이 작업의 본체다. 아래 "자료조사".
3. **쓴다.** 아래 "검토 기준" 아홉 항목과 "표기 규칙"이 곧 작성 기준이다.
4. **검토한다.** "반복 검토" 방식으로 노트 전체를 보고, 개발 서버 렌더와 `npm run build`
   (postbuild `check-lecture-notes.mjs`) 통과를 확인한다. 빌드는 GitHub의 과목 콘텐츠를
   동기화하므로 push 전에는 개발 서버에서 확인하고 push 후 다시 빌드한다. 사용자가 하나씩
   검토하는 단계에서는 지적한 부분과 거기 걸린 용어·링크·선행 설명까지만 고치고, 다른 노트의
   전면 개편은 새로 시작하지 않는다.
5. **커밋·push한다.** 아래 "커밋과 push".

## 자료조사

- **쓰거나 그리기 전에 그 주제를 가장 잘 설명한 자료를 실제로 연다.** 원논문, 공식 문서, 검증된
  해설(블로그·강의·영상), 기존 그림·시각화가 대상이다. 기억으로 쓰지 않는다.
- **사실·수식·수치는 1차 출처로 확정하고, 개념은 처음 제시했거나 표준이 된 정본을 인용한다.**
  예: RoPE → Su et al. 2021, 블로그 아님.
- **무료 접근본을 우선한다.** arXiv·open access·저자 PDF·공식 무료판. 페이월이면 무료 대안을 병기한다.
- **잘 풀어 쓴 2차 자료를 찾아 설명 방식·비유·그림을 참고한다.** 예: Transformer라면
  "The Illustrated Transformer". 쓸 만하면 출처를 달아 `<Figure>`·`<Video>`나 각주로 싣는다.
- **좋은 그림이 있으면 라이선스 확인 후 링크·임베드가 1순위다.** 인라인 `<svg>` 자작은 대응
  자료가 정말 없을 때의 최후 수단이다. 재사용 후보 모음은 `lecture-site-reference.md`.
- **자료가 엇갈리면 원논문을 따르고**, 흔한 오해는 `<Callout type="warning">`으로 짚는다.

## 검토 기준

작성자의 자체 검토, 도구 간 리뷰, 사용자 검토가 모두 이 아홉 항목을 쓴다. 노트 하나뿐 아니라
앞뒤 주차와의 연결까지 본다.

1. **사실.** 수치·인용·쪽 번호·서지정보가 원자료와 맞고, 근거보다 강한 해석이 없다. 원자료의
   보고값, 그 값으로 새로 계산한 값, 교육용 가상 예시를 구분해 밝힌다. 원자료 자체의 오류는
   조용히 따르지 않고 밝히며, 문헌이 엇갈리거나 정설이 없는 대목은 그렇다고 말한다.
2. **출처.** 각주마다 실제로 열어 저자·연도·제목·venue·arXiv 번호를 대조하고, 인용한 자리의
   주장이 그 자료의 그 위치(절·표·그림)에 있는지 본다. 기억으로 인용하지 않는다.
   - 주장 강도에 출처를 맞춘다. 실험 수치·그림은 원논문의 표·그림 번호까지 대고, 직관·비유는
     2차 해설도 되지만 해설임을 드러낸다.
   - 비슷한 주제의 다른 논문이나 2차 해설이 원논문 자리에 들어가 있지 않은지, 링크가 열리고
     안정적 식별자를 가리키는지, 과목별 참고문헌 규칙과 그림·영상의 라이선스·출처 표기를
     지켰는지도 본다.
3. **흐름.** 주차의 목표가 한 줄기로 이어지고, 각 절이 앞에서 무엇을 받아 다음으로 넘기는지
   드러난다. 지금 순서가 최선인지 따진다.
   - 선행 개념은 쓰기 전에 설명한다. 뒤 주차에 예정된 내용이어도 지금 필요하면 최소한의 기초를
     먼저 두고, 뒤 주차는 짧은 복습과 링크에서 출발해 심화한다.
   - 같은 논점은 가장 잘 맞는 곳에서 한 번만 쓴다. 되풀이할 자리에는 "§2-1 참고"처럼 참조를
     두고, 맨 끝 정리 절도 앞 문장을 반복하지 않고 새 문장으로 쓴다.
   - 문제 상황·작동 원리·작은 예시를 잇되, 모든 절에 같은 제목과 설명 틀을 기계적으로 반복하지 않는다.
     예시는 무엇이 문제이고 적용 전후 무엇이 달라지는지 보이게 한다.
   - 본문 절은 `##`, 하위 절은 `###`로 쓴다(좌측 목차가 이 둘만 모은다). 제목은 개념 중심의
     짧은 명사구로, 목차만 읽어도 줄기가 보이게 쓴다. 상위 제목은 하위를 포괄하고 하위는 상위를
     되풀이하지 않으며, 같은 수준은 한 축(예: 분석 단계)과 한 형식으로 맞춘다. 콜론 부제·질문형·
     동작형("~하기", "~읽는 법")을 섞지 않는다. 번호 형식은 과목 규칙을 따르고 좌측 목차
     줄바꿈도 본다.
4. **노트 사이의 연결.** 같은 주차와 앞뒤 주차의 노트가 용어·기호·모델 버전·수치를 같게 쓴다.
   한 개념이 두 노트에 걸칠 때 빠지거나 겹치는 조각이 없고, 노트 간 링크가 맞는 노트의 맞는 절을
   가리키며, 주차 도입의 지도(표·계보 요약)가 실제 노트 구성과 일치한다. 앞 주차에서 설명한 것은
   다시 풀어 쓰지 않고 짧은 복습과 링크로 받는다.
5. **읽기만으로의 이해.** 추상적인 설명마다 구체적인 예가 따르고, 어려운 계산·메커니즘은 실제
   값으로 한 단계씩 밟아 보인다(worked example).
   - 같은 개념을 두 번 설명해도 안 통하면 산문을 늘리지 말고 예시·도식으로 바꾼다.
   - 직관이 막히면 일상적인 비유와 작은 예시로 풀고, 실제 개념·수식에 연결한 뒤 비유의 한계를
     밝힌다. `eli5` 스킬을 쓸 수 있으면 활용한다.
   - 용어·변수·약어는 처음 쓸 때 정의하고, 독자가 "왜?"라고 묻게 되는 비약을 남기지 않는다.
     토론 질문에는 본문에서 답을 찾을 재료가 있어야 한다.
   - 수식은 직관과 함께 두고, 긴 유도는 `<Details>`로 접는다.
6. **시각 자료.** 글보다 그림·표·영상이 빨리 전달하는 곳에 시각 자료가 있다. 자작 도식은 기존
   자료를 찾아도 없을 때만 쓰고(자료조사), 실제 데이터나 사례 값으로 그렸다. 그림은 본문과 같은
   기호·같은 예시를 쓰고, 캡션만 읽어도 무엇을 보라는지 알 수 있다.
7. **수업 적합성.** 핵심과 선택 심화(`<Details>`)가 구분되고, 곁가지는 `<Sidenote>`, 직관·주의·
   예시 강조는 `<Callout>`에 둔다. 수업 중 활동은 범위와 완료 기준이 분명하다. 분량은 수업
   시간에 맞추지 않으며, 분량 조정이나 더 구체적인 서술은 사용자가 요청할 때만 한다.
8. **문장.** 사람이 처음부터 우리말로 쓴 글처럼, 소리 내 읽어 걸리지 않게 쓴다.
   - 번역투를 뺀다. 예: "~에 있어서", "~되어진다", "~라고 할 수 있다"의 남발, "~에 다름 아니다", "각도(angle)".
     영어 자료를 옮겨 쓸 때 특히 새어드니, 원문 없이 처음부터 썼다면 이렇게 쓸지 자문한다.
   - 같은 어미·접속사·문형의 연속, 명사만 이어 붙인 문장, 영어 용어에 어색하게 붙은 조사,
     구호식 단문, `**굵게**`·불릿 남발, 균일한 문장 길이와 매 절 같은 마무리를 손본다. 불릿과
     산문은 리듬 있게 섞는다.
   - 문단의 첫 문장이 요지를 말하고, 한 문단에는 요지 하나만 둔다.
   - 군더더기를 뺀다. 예: "아래 있다" 같은 위치 안내, "이번 주 N번째 노트에서" 같은 전방 참조,
     "관심 있으면 미리 봐도 좋다" 같은 곁다리. "이 문장이 없으면 독자가 못 따라가나?"로 훑는다.
   - 단정을 절제한다. "A가 아니라 B다", "전혀·항상·반드시", "의미가 0"은 근거가 확실할 때만 쓰고,
     대개 "A보다 B가 주가 된다"처럼 정도로 쓴다. 기억용 heuristic(kill criteria 등)은 의도적으로 강하게 써도 된다.
   - 기법·단계에 중요도 서열을 매기지 않는다. 예: "모델링은 덜 중요하다" 대신 "여기서 실수하면
     되돌리기 비싸다"처럼 하려는 말을 쓴다.
   - 톤·구성 참고: <https://thinkingmachines.ai/blog/interaction-models/>
9. **표기와 렌더.** 아래 "표기 규칙"과 "남의 저작물"을 지킨다. 렌더는 개발 서버에서 실제 페이지를
   열어 수식·SVG·각주 번호·목차 줄바꿈·별표 노출을 확인한다.

**반복 검토.** 한 라운드는 노트 하나를 처음부터 끝까지 읽고 위 기준을 모두 적용하는 것이다.
지적은 `[심각도] 파일:줄 — 문제 — 근거 — 제안`으로 남기고, 수정한 뒤에는 개발 서버에서 렌더를
확인한다. 다음 라운드는 고친 자리만 다시 보지 않고 노트 전체를 다시 읽는다(수정이 흐름을
바꾼다). 새 지적이 없는 라운드가 나오면 끝낸다. 라운드 기록은 repo 밖에 둔다.

## 표기 규칙

- **em dash로 문장을 잇거나 부연하지 않는다.** 본문·제목·캡션·출처 모두 문장을 나누거나 쉼표·
  괄호·콜론을 쓴다. 출처의 정식 제목과 직접 인용문은 원문 표기를 보존하고, 페이지 범위의 en dash나
  기술 용어의 하이픈과 구분한다.
- **용어는 영어(technical term)가 기본이고, 한국어로 쓰는 핵심 용어는 노트의 첫 설명에만 원어를
  괄호로 병기한다.** 예: 처리량(throughput). 어색한 번역은 자연스러운 표현으로 고치고, 이미 설명한
  용어마다 괄호를 반복하거나 일반 문장까지 영어로 옮기지 않는다. 원어의 의미도 구분한다(sequence
  model과 sequential computation은 다르다).
- **약어는 처음 나올 때 full form을 병기하고 이후엔 약어만 쓴다.** 예:
  `RoPE(rotary position embedding)`, `GPU(graphics processing unit)`. 학회·저널명(NeurIPS)과
  제품·모델 고유명(BERT)은 예외.
- **인용은 GFM 각주 `[^의미-있는-슬러그]`로, 그 자리의 특정 주장을 직접 뒷받침할 때만 단다.**
  검증돼야 하는 주장이거나 더 파고들 독자를 위한 안내일 때만 넣고, "관련 문헌" 나열은 하지 않는다.
  키는 영문·숫자·`_`·`-`로만 쓴다(빌드 검사가 이 범위의 미정의 키만 잡는다).
- **각주 정의는 서지정보와 링크만, 한 노트 안에서 같은 형식으로 쓴다.** 형식:
  `저자(성, 이니셜). (연도). 제목. *매체/venue*. 권(호), 페이지. [링크](URL).` 링크는 안정적
  식별자(arXiv abs·DOI·저자 도메인)에 걸고, 없으면 venue 표기로 충분하다(억지 링크 금지). 저자명은
  로마자, 제목은 원어 그대로.
  - 내용 요약·인용 이유·절 목록·수업 활용 설명은 붙이지 않는다. 특정 절·그림을 읽어야 이해되면
    그 안내는 본문이나 캡션에 둔다.
  - 접근일·열람일·확인일은 참고문헌과 본문 어디에도 적지 않는다.
  - 블로그·공식 문서에는 확인 가능한 발행·수정 연도나 버전을 적고, 방문한 연도로 대신하지 않는다.
    발행 연도·판본 같은 식별 정보와 이미지의 라이선스·수정 여부는 보존한다.
- **다른 문헌의 절·표·그림 번호는 노트의 절과 헷갈릴 때만 출처를 붙인다.** 노트 절은 `§3-2`,
  논문 절은 대개 `§3.2`라 보통은 "(Table 2)", "(§4.4)"로 충분하다. `§1` 같은 한 단계 번호, 노트
  절과 겹치는 번호, 한 문장에 노트 절과 함께 나올 때, 문장에서 출처가 바로 드러나지 않을 때만
  "(원논문 §1)", "(서베이 §4)"처럼 쓰고, 한 문단 안에서는 표기를 섞지 않는다. 다른 노트의 절은
  "06b §4-1"처럼 노트 이름을 붙이고 링크한다.
- **공개 노트에서 아직 비공개인 주차로 직접 링크하지 않는다.** 필요하면 주차명만 안내하고, 주차 간
  링크를 바꾸면 제한 공개 설정으로도 빌드한다(방법은 `lecture-site-reference.md` "학생 사이트 공개 주차").
- **문장부호로 끝나는 강조 뒤에 조사가 바로 붙으면 `<strong>`을 쓴다.** 예:
  `**시퀀스 모델(sequence model)**은`은 별표가 노출되니 `**시퀀스 모델**(sequence model)은`이나
  `<strong>시퀀스 모델(sequence model)</strong>은`으로 쓴다. 괄호·따옴표·물음표 모두 해당하며, 조사를
  띄우거나 보이지 않는 문자를 넣지 않는다([CommonMark 강조 규칙](https://spec.commonmark.org/0.31.2/#emphasis-and-strong-emphasis)).
- **표의 구분 행은 `---`만 쓴다.** 정렬 표시(`:---`, `---:`, `:---:`)는 인라인 style로 바뀌어
  CSP·빌드 검사에 걸린다.
- **디스플레이 수식은 `$$`를 각각 별도 줄에 두고, heading에는 `$수식$`을 넣지 않는다.** 한 줄
  `$$...$$`는 인라인 취급되고, heading의 수식은 목차를 깨뜨리니 유니코드로 쓴다.
- **`.mdx` 본문에서 `<` 뒤에 글자가 아닌 문자가 오면 `MDXError`가 난다.** 예: `(<)`. 부등호는
  `≤`나 백틱 코드로 쓴다. 텍스트의 `{`도 JS 표현식으로 해석된다(인라인 수식 안은 무방).
- **스크립트(Python 등)로 노트에 수식을 넣을 때는 raw string을 쓴다.** 일반 문자열이면 `\text`·
  `\to`가 탭 문자로 바뀌어 수식이 조용히 깨지고 `merror` 검사로도 잡히지 않는다. 수정 후 노트에
  탭 문자가 없는지 확인한다.

## 남의 저작물

강의 노트 repo는 **public**이라 올리는 건 재배포다. 남의 글·그림·코드는 **넣기 전에** 근거(라이선스·
출처)를 확인한다. "수업용이니까"는 근거가 아니다. 저작권은 *표현*을 보호하고 *아이디어·방법·사실*은
보호하지 않는다.

- **개념·방법·수식·실험 사실은 읽고 이해해서 우리 말·우리 구조로 쓴다.** 문단은 옮기지 않는다.
  문단별로 바꿔 써도 구조·순서·예시 배열을 가져오면 근접 모방(2차적저작물)이다. 판별: 원문 옆에
  두고 "저걸 우리말로 바꾼 것"으로 읽히면 위험하다.
- **핵심 정의문도 번역해 옮기지 않는다.** 우리 말로 다시 쓰고, 원문이 꼭 필요하면 한두 문장만
  따옴표와 출처로 인용한다(번역 인용 가능, 저작권법 §28). 프레임워크 용어(PCS 등)를 우리 말로
  정의하는 건 자유다.
- **그림은 파일마다 이용 조건을 확인한다.**
  - CC 자료: 저자·출처·저작권 표시·라이선스 링크와 별도 권리 표시를 본다. 무료 공개·교육 목적만으로
    NC 충족을 단정하지 않고, ND는 번역·변형본 공유를 허용하지 않으며, 버전은 추정하지 않는다
    ([CC 공식 FAQ](https://creativecommons.org/faq/)).
  - 출판 논문·arXiv 그림: 개별 권리와 인용 요건(분량·목적·주종 관계)을 검토한다.
  - Wikimedia Commons는 파일 페이지에서 확인한다. CC 표기 없는 블로그(Thinking Machines 등)는
    전권 보유로 보고 그림을 임베드하지 않는다.
- **자르기·라벨 번역·다시 그리기도 변형일 수 있고, 핫링크도 판단 대상이다.** 다시 그렸다는 이유만으로
  이용 문제가 풀리지 않는다. 자작 도식은 원본의 표현·배치를 옮기지 않고 개념을 독립적으로 구성한다.
- **근거를 확정하기 어려우면 원문 페이지를 링크한다.** 재사용이 꼭 필요하면 공개 배포 범위를 밝혀
  권리자에게 허락을 구한다.
- **`source` 표기:** `저작자 · 출처 · 라이선스(버전 모르면 생략) · "수정 없음"`. 재현 그림이면
  원 개념 출처도 적는다. 예: `그림 Y. Jia, Wikimedia, CC BY-SA 3.0 · 아키텍처는 Vaswani 2017`.
- **코드·데이터·사진·영상:** 코드는 repo `LICENSE`를 확인하고(없으면 복사 금지), 데이터셋은
  재배포·게재 허용 여부를 본다. 스톡 사진은 쓰지 않는다. `<Video>`(YouTube/Vimeo) 임베드는 링크라
  가능하다. 애매하면 안 쓴다.
- **교재가 있으면 노트를 교재의 "다리"로 만든다.** 해당 장을 노트 안에서 지정 읽기로 링크하고, 노트는
  교재에 없는 것(과목 맥락·학생 도메인 예시·"우리 프로젝트에 어떻게 적용하는지")을 쓴다.

## 커밋과 push

- **강의 자료는 `pnu/lectures/<학기>/<과목>/` 클론에서만 고친다.** `milab-pnu/lectures/`는 sync가
  매번 덮어쓰는 빌드 입력물이라 커밋하지 않는다.
- **과목 repo는 알아서 커밋·push하고, `milab-pnu` push만 사용자에게 묻는다.** 과목 repo는 되돌리기
  쉽고 push 1~2분 뒤 반영된다. push 후 CI는 사용자가 요청할 때만
  `gh run list -R milab-pnu/milab-pnu.github.io --limit 1`로 한 번 확인한다.
- **GitHub 쓰기 API를 몰아서 호출하지 않는다.** 예: `gh`를 짧은 시간에 루프로 십수 번, 여러 repo에
  걸쳐 부르면 어뷰징 탐지로 계정이 정지된다(실제로 겪음, 복구에 며칠). 소량씩 간격을 둔다.
- **repo는 public이다.** 비밀정보·비공개 개인정보를 넣지 않는다. 언어는 한국어(커밋 메시지·주석 포함).
- **공동 작성자 규칙.** Claude Code·Codex가 작성하거나 수정한 모든 커밋(과목 repo와 `milab-pnu`)에
  `Co-Authored-By`를 반드시 추가한다.
  - 기본 표기는 `Co-Authored-By: Codex <noreply@openai.com>` 또는
    `Co-Authored-By: Claude <noreply@anthropic.com>`. 실제 모델명이 확인되면 도구 이름에 병기하되
    특정 모델을 고정하지 않고, 확인이 안 돼도 기본 표기로 남긴다.
  - 실제 참여한 도구만 적고, 둘 다 참여했으면 한 줄씩 적는다. 본문 뒤 빈 줄을 두고 추가하며,
    기존 공동 작성자는 보존하고 중복은 피한다.
  - 커밋 후 `git log -1 --format=%B`로 누락을 확인한다. 이미 push한 커밋의 소급 수정은 사용자가
    요청할 때만 한다.
  - 표기 근거: [Codex 공식 소스](https://github.com/openai/codex/blob/e4a3612/codex-rs/core/src/commit_attribution.rs),
    [Claude Code 문서](https://code.claude.com/docs/en/configuration).
